# Revenue Pulse｜广告收入经营分析 v0.3 MVP 开发计划

> 版本：v0.3  
> 日期：2026-07-27  
> 状态：已批准  
> 依据：已批准的 v0.3 PRD、UI/UX 规范和技术方案  
> 执行方式：一个 Issue、一轮开发、一次验收；用户批准后才进入下一个 Issue  
> 公开边界：只有模拟看板可以匿名公开；真实数据及其分析结果始终受保护

## 1. MVP 目标

v0.3 MVP 完成后，应当形成两个清晰分离的产品面：

### 1.1 公开模拟看板

任何人打开链接即可查看，不需要登录。

看板使用程序生成的模拟数据，能够完整演示：

- 广告收入及环比、同比；
- `VV × Ad Load × eCPM` 流量变现路径；
- `GMV × 广告货币化率` GMV 变现路径；
- 收入变化贡献；
- 广告形式、场景、计费方式、类目和广告主分层；
- 广告主 ROI 与留存；
- 用户体验和自然交易护栏；
- 数据质量、指标口径和证据链；
- 不包含任何预算指标或预算结论。

### 1.2 受保护的真实数据工作区

获准用户登录后可以：

- 上传 CSV 或 Excel；
- 在浏览器内识别数据源、字段和粒度；
- 确认收入口径；
- 查看当前数据能支持哪些分析；
- 生成受治理的广告收入分析；
- 审核管理简报；
- 人工确认后推送飞书。

原始文件默认不离开浏览器。真实数据及其分析结果不能发布到公开看板。

## 2. MVP 成功标准

MVP 不是“页面看起来完成”，而是以下业务闭环全部成立：

```text
模拟数据
→ 粒度安全的数据管道
→ 确定性指标计算
→ 双路径收入归因
→ 公开模拟看板

真实文件
→ 本地解析与字段确认
→ 数据质量和可用性判断
→ 受保护的聚合分析
→ 人工审核
→ 飞书推送
```

最终必须满足：

1. 数字可勾稽；
2. 指标不会因跨粒度关联而重复；
3. 缺失数据不会被补零或伪造；
4. AI 不能修改受治理数字；
5. 预算内容不会进入 v0.3；
6. 公开接口只能读取模拟结果；
7. 真实数据结果不能被公开；
8. 每条管理结论可以追溯到指标和数据源；
9. 每个开发阶段可以独立验证和回滚。

## 3. MVP 范围

### 3.1 本期包含

- v3 数据合同与验证器；
- 粒度感知的指标聚合；
- 广告收入、Ad Load、填充率、eCPM、CTR、CPC、CPM；
- GMV、广告货币化率、广告 ARPU；
- 广告主 ROI、活跃、新增、留存和流失；
- 用户体验与自然交易护栏；
- Shapley 和 GMV 中点贡献分解；
- v3 模拟数据、注册表、管道和快照；
- Revenue Skill 2.0；
- v3 Worker API 和 D1 保存；
- 公开模拟看板；
- 受保护的数据上传、映射和分析工作区；
- 管理简报审核和飞书推送；
- GitHub Actions 时间审计；
- 自动测试、部署和回滚。

### 3.2 本期不包含

- 月底收入预测；
- 预算读取、计算、展示和推送；
- 自动收入确认或关账；
- 自动调整广告位、底价或竞价机制；
- 没有实验支持的因果推断；
- 把真实数据分析发布成公开链接；
- 多公司、多租户和复杂角色权限；
- 复杂机器学习模型；
- 无人审核的真实数据飞书推送。

## 4. 开发原则

### 4.1 每轮只做一个 Issue

每个 Issue 必须包含：

- 目标；
- 范围；
- 不做什么；
- 验收条件；
- 测试方法；
- 依赖；
- 回滚方式。

执行流程：

```text
待开发
→ 开发中
→ 待测试
→ 待审查
→ 用户批准
→ 已完成
```

用户未批准时：

- 不认领下一个 Issue；
- 不合并额外功能；
- 不部署下一阶段；
- 不发送真实飞书测试消息。

### 4.2 小步兼容

- v3 使用独立合同、管道和快照；
- 当前 v1 页面和 API 在迁移期继续可用；
- D1 只新增表，不删除旧表；
- 功能开关默认关闭；
- 每次变更只触及当前 Issue 所需文件；
- 线上切换前保留可恢复的上一版本。

### 4.3 数字先于文案

开发顺序必须是：

```text
数据合同
→ 指标公式
→ 质量规则
→ 贡献分解
→ API 结果
→ 页面
→ Skill 文案
→ 飞书
```

不能先画完整页面，再用临时数字填充。

## 6. M0：固定基线和迁移护栏

### 目标

在修改指标前，确保现有项目状态可验证、可对比、可回滚。

### 交付物

- 记录当前主分支、线上版本和构建结果；
- 为现有 v1 关键页面和 API 增加基线测试；
- 增加 `ENABLE_AD_REVENUE_V3=false`；
- 建立 v3 文件和路由命名边界；
- 明确旧 Sales-only Issues 暂停执行；
- 保存当前模拟快照作为回归夹具；
- 不修改线上行为。

### 验收

- 当前生产构建通过；
- 当前 v1 页面核心 KPI、API 和飞书卡片结构有基线测试；
- 功能开关关闭时，页面和接口与当前版本一致；
- Git 工作区只包含本阶段预期变更；
- 没有部署或发送飞书。

### 回滚

删除新增的测试和功能开关接线即可；现有业务代码不应发生行为变化。

## 7. M1：v3 数据合同与计算内核

### 目标

先把所有受治理数字做成独立、可测试的纯函数，不依赖页面和 AI。

### 交付物

- `RevenueAnalysisInputV3`；
- `RevenueAnalysisResultV3`；
- 数据源、字段、粒度和维度合同；
- 收入口径状态；
- 指标可用、警告、不可用和阻断状态；
- Ad Load、请求率、填充率、渲染率、eCPM；
- CTR、CPC、CPM；
- GMV、广告货币化率、广告 ARPU；
- 广告主 ROI 和留存；
- 用户体验护栏；
- 流量路径 Shapley 分解；
- GMV 路径中点分解；
- 预算字段禁用验证器。

### 验收

- 每个公式都有正常、缺失、零分母、负数和异常输入测试；
- 基础流量公式与收入回算一致；
- Ad Load 与填充率不重复计算；
- Shapley 贡献之和等于收入变化；
- GMV 两项贡献之和等于收入变化；
- 粗粒度指标不能被请求到更细粒度；
- 所有不可用指标都有明确原因；
- 合同输入和输出不包含预算业务字段；
- AI 不参与任何指标计算。

### 回滚

v3 计算模块尚未接入页面和旧 API，可整组撤回，不影响线上 v1。

## 8. M2：v3 模拟数据与粒度安全管道

### 目标

生成足够真实、但完全匿名的演示数据，覆盖双路径分析和主要风险场景。

### 交付物

- `source_registry_v3.json`；
- v3 模拟数据生成器；
- v3 数据管道；
- `dashboard-v3.json`；
- 与收入同粒度的广告交付事实；
- 广告请求和填充数据；
- GMV 和归因 GMV；
- 用户行为和自然转化；
- 广告主活跃和留存；
- 策略事件；
- 总量守恒和关联质量报告；
- 数据来源标记 `dataClassification="demo"`。

### 演示场景

模拟数据至少包含：

1. 收入增长主要由流量拉动；
2. Ad Load 提升但用户体验恶化；
3. 填充下降导致广告机会浪费；
4. eCPM 提升但广告主 ROI 下降；
5. GMV 增长但广告货币化率下降；
6. 某类目或流量场景产生主要负向贡献；
7. 广告主留存下降；
8. 某条分析路径因数据缺失而降级。

### 验收

- v3 管道可重复运行；
- 同一随机种子产生稳定结果；
- 所有数据均为程序生成；
- 不包含个人信息、企业真实数据或密钥；
- 注册表不读取预算源；
- 关联前后收入、曝光和 GMV 总量守恒；
- 快照通过 v3 合同验证；
- 每个演示场景都有预期指标和结论；
- v1 管道仍能独立运行。

### 回滚

删除独立 v3 注册表、生成器、管道和快照；v1 的 24 源文件不修改、不删除。

## 9. M3：Revenue Skill 2.0、API 与 D1

### 目标

把确定性分析接入服务端，保存可追溯版本，并严格隔离公开模拟结果和真实结果。

### 交付物

- Revenue Skill 升级至 2.0；
- 新指标合同、质量护栏、归因规则和简报标准；
- v3 brief 校验器；
- `/api/v3/public/latest`；
- 受保护的 v3 分析创建和读取接口；
- v3 D1 表和新增式迁移；
- 输入 digest；
- AI 语言增强与规则回退；
- `demo_public` 和 `private` 服务端约束；
- 公开接口数据最小化。

### 验收

- 规则引擎可在无模型密钥时完整运行；
- AI 失败不会影响数字和保存；
- AI 不能覆盖指标对象；
- 只有 `dataClassification="demo"` 可以成为 `demo_public`；
- `dataClassification="real"` 永远只能是 `private`；
- 服务端不存在“把真实分析改成公开”的接口；
- 匿名用户只能读取公开模拟结果；
- D1 迁移不影响旧 `analysis_runs`；
- brief 校验器拒绝预算内容；
- 旧 API 和 v1 看板仍可运行。

### 回滚

关闭 v3 功能开关，保留新增表但停止读写；旧 API 和旧看板继续工作。

## 10. M4：公开模拟看板

### 目标

交付第一个用户可见成果：无需登录即可查看的 v3 模拟分析看板。

### 交付物

- 收入口径和数据状态上下文条；
- 六张核心 KPI 卡；
- 收入趋势；
- 流量变现和 GMV 变现页签；
- 公式因子卡；
- 请求、填充、曝光和点击漏斗；
- 收入贡献瀑布图；
- 广告形式、场景、计费方式、类目和广告主分层下钻；
- 广告主 ROI、活跃和留存；
- 用户体验与自然交易护栏；
- 数据质量中心；
- 指标口径与证据抽屉；
- 规则生成的管理简报；
- 匿名访问。

### 验收

- 匿名浏览器可直接打开；
- 页面只读取 `demo_public`；
- 页面明确标记“模拟数据”；
- 页面无预算指标、趋势线、差异或文案；
- 两条收入路径与快照数字一致；
- 贡献桥可以勾稽；
- 缺失数据有原因和补充建议；
- 所有图表有表格或列表替代；
- 375、768、1024、1440px 无页面级横向溢出；
- 键盘、焦点、对比度和状态表达通过检查；
- 生产构建和页面回归测试通过。

### 发布门

完成本地和预览验收后，由用户决定是否替换当前公开模拟看板。未批准前不切换生产链接。

### 回滚

关闭 v3 看板开关或切回上一 Sites 版本。

## 11. M5：受保护的真实数据工作区

### 目标

让用户在不知道数据结构的情况下，安全判断“手里的数据能分析什么”。

### 交付物

- 受保护的 `/workspace`；
- CSV 和 Excel 浏览器解析；
- 数据源分类；
- 字段画像和样例预览；
- 收入口径确认；
- 字段映射；
- 粒度和主键识别；
- 数据可用性报告；
- 质量阻断与局部降级；
- 本地关联和共同粒度聚合；
- 服务端重新计算；
- 私有结果读取；
- 映射复用。

### 保护规则

- 原始文件不上传；
- 样例值不上传；
- 预算字段只在本地标记为忽略；
- 服务端只接收受控聚合；
- 所有真实分析写入 `private`；
- 未登录或未获准用户不能创建、读取或保存真实分析；
- 如果身份能力不可用，真实数据服务端功能保持关闭。

### 验收

- 至少一份 CSV 和一份 Excel 可以完成完整流程；
- 用户必须确认收入口径；
- 数据缺失时路径正确降级；
- 粗粒度指标不能错误下钻；
- 刷新前的映射进度可恢复；
- 用户不能读取其他用户分析；
- 原始文件和样例值未出现在网络请求、D1 和日志；
- 真实分析不能被公开 API 读取；
- 移动端可以查看和审核，桌面端可以完成字段映射。

### 回滚

关闭真实数据保存功能开关；公开模拟看板不受影响。

## 12. M6：管理简报、飞书与时间审计

### 目标

形成“先审核、再发送”的管理闭环，并能解释 09:45 计划任务为何晚到。

### 交付物

- v3 管理简报；
- 事实、判断、风险和待验证标签；
- 人工审核记录；
- digest 防止审核后内容变化；
- 飞书发送幂等键；
- 无预算的 v3 飞书卡片；
- 发送成功、失败和重试状态；
- Actions 和分析全链路时间戳；
- 延迟分段展示。

### 时间记录

```text
scheduled_at
started_at
pipeline_finished_at
analysis_finished_at
feishu_sent_at
completed_at
```

### 验收

- 未审核不能发送；
- 质量 `fail` 不能发送；
- 输入或简报变化后旧审核失效；
- 同一幂等键不会重复发消息；
- 卡片展示收入、主要贡献、Ad Load、eCPM、货币化率和风险；
- 卡片不展示预算和月底预测；
- 可以区分 GitHub 调度、管道、分析和飞书发送延迟；
- 只有在用户明确批准测试时才发送真实飞书消息；
- 自动飞书默认保持关闭。

### 回滚

关闭手动和自动飞书开关；分析和看板仍可继续使用。

## 13. M7：完整验收、发布和交接

### 目标

证明 MVP 可以稳定运行、公开分享、安全处理真实数据并随时回滚。

### 交付物

- 完整测试报告；
- 数据合同和指标目录；
- 公开/私有隔离测试；
- 匿名验收夹具；
- 性能与可访问性检查；
- 数据保留和删除规则确认；
- GitHub Actions 运行记录；
- Sites 生产版本；
- README 和交接档案更新；
- v0.3 迭代记录；
- 回滚演练记录。

### 最终验收

- 公开模拟链接无需登录；
- 公开页面只有模拟数据；
- 真实数据结果不可公开；
- 两条收入路径完整；
- 所有核心公式和贡献勾稽；
- 无跨粒度重复；
- 无预算业务输出；
- 数据缺失和质量阻断行为正确；
- AI 不能修改数字；
- 飞书人工审核、digest 和幂等正常；
- 自动化延迟可追踪；
- 构建、单元、合同、集成、页面和安全测试通过；
- 可以切回上一线上版本。

### 生产发布

只有用户批准最终验收后才：

1. 保存生产版本；
2. 部署公开模拟看板；
3. 为获准用户开启真实数据工作区；
4. 开启人工飞书；
5. 再单独决定是否恢复自动飞书。

## 16. 每个 Issue 的交付模板

### 开始前

- 确认上一个 Issue 已批准；
- 拉取最新主分支；
- 检查未提交修改；
- 将 Issue 移到“开发中”；
- 重述本轮范围和不做内容。

### 开发中

- 只修改当前 Issue 需要的文件；
- 先写或更新失败测试；
- 实现最小代码；
- 运行本轮测试；
- 检查没有真实数据和密钥；
- 检查没有预算内容回流。

### 提交审查

向用户提供：

- 解决了什么问题；
- 修改了哪些区域；
- 测试结果；
- 可验证方式；
- 已知限制；
- 回滚方式；
- 是否影响线上；
- 是否发送过飞书。

### 审查后

- 用户批准：Issue 移到“已完成”，再认领下一个；
- 用户要求修改：Issue 保持“待审查”，只修本 Issue；
- 用户拒绝：回滚本 Issue，不影响已批准阶段。

## 18. 主要风险和控制

| 风险 | 影响 | 控制方式 |
|---|---|---|
| 实际文件结构未知 | 字段识别和关联可能不适配 | 先做画像、确认和共同粒度降级 |
| 跨粒度重复 | eCPM、CTR、货币化率错误 | 粒度合同、总量守恒和阻断测试 |
| Ad Load 与填充重复 | 收入回算放大 | 基础路径和展开路径互斥 |
| 收入口径不清 | 把消耗当财务收入 | 口径必选、状态标签、服务端再校验 |
| 真实数据泄露 | 严重安全问题 | demo/real 强制分类、公开接口负向测试 |
| AI 生成虚假原因 | 管理层误判 | AI 只读受治理结果，非法输出回退 |
| 功能范围过大 | MVP 长期无法验收 | 先公开模拟看板，再真实工作区 |
| Actions 延迟 | 计划和实际消息时间不一致 | 六段时间戳审计 |
| 飞书重复发送 | 管理干扰 | 审核 digest 和幂等键 |
| 旧 v1 被破坏 | 线上不可用 | 独立 v3、功能开关和上一版本回滚 |
