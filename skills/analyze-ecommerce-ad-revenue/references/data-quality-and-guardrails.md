# 数据质量与分析护栏

## 数据源控制

每个数据源都要记录：

- 稳定的数据源 ID 和名称；
- 业务负责人，条件允许时同时记录技术负责人；
- 数据粒度；
- 主键或复合主键；
- 关联键；
- 预期更新时效；
- 实际更新时间；
- 已覆盖的业务日期范围。

## 必做检查

### 及时性

把最近一次成功更新时间与数据源时效和报告截止时间进行比较。

- 如果决定性数据源已超出时效且没有批准的替代数据，阻断相关结论。
- 不能因为多数非关键数据源正常，就用平均健康分掩盖关键数据源延迟。

### 完整性

分别检查必填字段完整率和应有期间的数据覆盖率。

- 缺失 ID、日期、金额和状态字段属于关键问题。
- 区分“缺少记录”和“真实业务活动为零”。

### 唯一性

按照登记的数据粒度检查主键。

- 如果重复主键会导致收入在关联后被重复计算，立即停止关联。
- 必须使用有业务依据的规则处理重复值，禁止随意删除一行。

### 关联成功率

同时计算已匹配和未匹配的行数及金额。

- 除行数覆盖率外，还必须检查金额覆盖率。
- 即使整体匹配率很高，也要调查未匹配的大额记录。

### 财务对账

对账经营流水、计费确认、财务确收、返点、退款和净收入。

- 设定明确的金额和比例容差。
- 将差异分为时间差、业务范围差、政策差异、数据错误或未解释差异。

## 发布门槛

优先使用公司正式阈值。MVP 尚无正式阈值时，使用：

| 检查项 | 通过 | 警告 | 失败 |
|---|---:|---:|---:|
| 关键数据源及时性 | 在时效内 | 延迟不超过12小时 | 延迟超过12小时 |
| 必填字段完整率 | ≥99.5% | 98.0%–99.5% | <98.0% |
| 主键唯一性 | 100% | 已用明确规则处理 | 存在未解决重复 |
| 关联金额覆盖率 | ≥99.5% | 98.0%–99.5% | <98.0% |
| 财务对账差异率 | ≤0.5% | 0.5%–1.0% | >1.0% |

任一关键检查失败时，整体状态设为 `fail`。没有失败但存在警告时，整体状态设为 `warn`。

## 分析护栏

- 不能仅凭分组贡献或时间相关性推断因果。
- 不能发布缺少截止时间、关键假设和版本时间的预测。
- 不能把缺失财务数据填成零。
- 不能因为总体结果为正，就隐去负向动因。
- 判断收入下降是否不利前，先检查预算、预测、策略和可比期间。
- 不向无权限对象展示商家、员工或商业敏感明细。
- 不在代码、日志、卡片或公开仓库暴露 API 凭证、令牌、Webhook 或个人标识。
- 明确标注模拟数据、估算数据和人工调整数据。

## 数据缺口处理

每个缺口都要说明：

1. 缺少的数据源或字段；
2. 受影响的指标或结论；
3. 可能造成的偏差方向；
4. 临时处理方法；
5. 责任人和预计解决时间。

即使头部收入已经完成对账，只要缺口影响重要动因，也要下调相关结论的置信度。
