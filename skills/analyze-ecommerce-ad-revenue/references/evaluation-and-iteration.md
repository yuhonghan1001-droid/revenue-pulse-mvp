# 评测与迭代机制

把 Skill 当作一项财务控制能力进行评测，不以文字是否流畅作为主要标准。

## 评测维度

每个案例按 0–2 分评分：

| 维度 | 0分 | 1分 | 2分 |
|---|---|---|---|
| 指标准确性 | 口径错误或混用 | 头部指标正确，但缺少信息 | 口径正确且受到治理 |
| 数据质量处理 | 忽略质量失败 | 只做文字提醒 | 正确阻断或降级结论 |
| 差异解释 | 没有量化 | 部分量化 | 动因金额桥完成对账 |
| 预测规范 | 没有假设 | 说明了假设 | 有版本且考虑敏感性 |
| 证据追溯 | 没有证据 | 只有部分来源 | 每项结论都能追溯 |
| 管理价值 | 没有行动 | 行动过于笼统 | 有责任人、时间和触发条件 |
| 不确定性 | 过度确定 | 只有统一免责声明 | 每项结论有独立置信度 |

发布要求：

- 指标准确性和数据质量处理不能出现 0 分；
- 总分至少达到 11/14；
- 已经通过的历史案例不能出现回退。

## 基准案例

### 案例 A：收入增长但月底预测低于预算

输入特征：

- 累计净收入同比增长；
- 截至当前基本符合时间进度；
- 近期运行速度放缓；
- 月底预测低于全月预算。

预期行为：

- 区分“同比增长”和“目标达成”；
- 核心结论突出预测风险，不能简单判断经营健康；
- 量化预测缺口并说明运行速度放缓的动因；
- 给出带触发条件的行动。

### 案例 B：策略调整导致表面收入下降

输入特征：

- 有意的流量或返点策略调整后，收入下降；
- 该策略影响已经体现在预算中；
- 另一个商家分组同时出现计划外走弱。

预期行为：

- 不把总收入下降自动判断为负面；
- 分开解释符合预期的策略影响和非预期商家问题；
- 找出真正需要采取行动的剩余差异。

### 案例 C：转化数据延迟

输入特征：

- 收入已经完成财务对账；
- 转化数据超出更新时效；
- 管理层要求解释 ROI。

预期行为：

- 在权限允许时继续发布已经对账的收入事实；
- 阻断或弱化 ROI 和转化结论；
- 说明缺失数据源、责任人和预计解决时间。

### 案例 D：重复主键导致关联膨胀

输入特征：

- 商家维表存在重复主键；
- 关联后收入事实行数和收入金额异常增加。

预期行为：

- 数据质量检查失败；
- 不发布被放大的收入指标；
- 指出重复数据源和修复要求。

### 案例 E：大促日期错位

输入特征：

- 自然日同比下降；
- 去年同一大促比今年晚一周。

预期行为：

- 把简单自然日同比标记为不可比；
- 增加按大促阶段对齐的比较；
- 在期间对齐前避免给出确定性趋势结论。

## 迭代记录

每次重要 Skill 变更都要在 Git 提交或 PR 中保留：

1. 被质疑的案例或新增需求；
2. 根因分类；
3. 抽象后的规则变化；
4. 新增或修改的评测案例；
5. 变更前后评分；
6. 历史案例回归结果。

提交案例前，删除真实金额、个人信息和商业敏感信息。

## 版本升级条件

同时满足以下条件，才能把修改称为 Skill 新版本：

- 分析行为或决策规则发生变化；
- 变化已经转化为评测案例；
- 新案例通过；
- 历史案例全部通过；
- 财务负责人完成审核。

只修改措辞属于文档优化，不属于能力升级。
